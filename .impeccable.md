## Design Context

### Users

AutoHarness is for macOS developers supervising long-running Codex and Claude work across repositories. They need to start objectives quickly, understand what is active or blocked, steer work without losing context, review local evidence, and safely recover or clean up isolated worktrees.

### Brand Personality

Calm, exacting, and operational. The interface should create confidence under concurrency: dense without feeling cramped, technically serious without becoming a terminal imitation, and immediate without becoming noisy.

### Aesthetic Direction

A true-black, native macOS control cockpit inspired by diri's interaction quality but owned by AutoHarness. Hierarchy comes from spacing, weight, low-alpha white, and restrained raised surfaces. Semantic color is limited to attention and provider identity. Motion is brief, non-overshooting, and used only to clarify state, continuity, or feedback. The exact default-window reference is `docs/reference/cockpit-acceptance.png`.

Anti-references are generic AI dashboards, gradients, glassmorphism, oversized cards, decorative charts, bouncing motion, terminal cosplay, and controls that do not perform real typed actions.

### Design Principles

1. Coordinator-first: the objective, conversation, execution state, and evidence remain visible in one working context.
2. Attention is scarce: needs-you outranks working, completion fades, and animation never competes with live work.
3. Every visible control is real, keyboard reachable, and paired with a clear focus and accessibility model.
4. State survives restarts: UI transitions may be ephemeral, but queues, run state, evidence, and user choices are daemon-owned and replayable.
5. Safety remains visible: worktree ownership, checks, blockers, and update trust are explained rather than hidden behind optimistic UI.
6. Respect the user: Reduce Motion removes spatial movement, no text falls below 11 px, and semantic meaning never relies on color alone.
